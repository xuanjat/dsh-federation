# 交付协议规范（handoff manifest）

- 版本：1.0（murmuration MVP）
- 一句话：**通知走房间，文件走既有通道，二进制永不进文本区。**
- 配套：[房间协议](room-protocol.md) · [治理与分发](../docs/03-governance.md)

## 1. 要解决的问题

多机协作里最危险的不是传不过去，而是**每个人自己发明一套传法**：临时目录约定、base64 塞正文、新写脚本另起通道……事后没人能回答"当时谁把哪个版本给了谁、凭什么信它没坏"。本协议把交付收敛到一条默认路径，让答案永远可查。

立规原话（人类负责人，2026-10-30）：「绝对不要擅自制定额外的通讯方案，重复造轮子。」

## 2. 通道分层

| 层 | 载体 | 只承载 | 不承载 |
|---|---|---|---|
| 通知层 | 房间三件套（inbox/、general.md、cursor/） | 指针、状态、回执 | 文件本体、base64 |
| 文件层 | 双方**既有**通道：ssh 只读挂载自取、演练过的 scp/rsync、外交官已验证的落点 | 任何体积、任何格式 | — |
| 存储层 | OV 资源区（viking://resources/…） | **仅文本**，且需长期共享 | 二进制（tar.gz/docx/png 会被解析成文本、核不了 sha256） |

**动手前自检**：「这是不是房间协议 + 本机外交官已经有的那条路？」答不上来就停下，报人类负责人拍板。

## 3. 外交官统一外发

任何会话要对外交付时：

1. **交本机外交官**：内容 append 到 `inbox/<本机>.md`，头写 `to: <本机>-diplomat`、`role: <自己的岗位>`；写清交付物路径 + sha256 + 字节数、收件人、取件与校验命令。
2. 外交官按房间协议统一外发、记账（更新分发台账）、汇总回执。
3. 例外：外交官缺席且人类点名"你亲自发"时才代发，正文注明「外交官未在，代发」。

**禁止**：绕过外交官直发他机；自建服务/webhook/新目录协议；文件塞正文或 base64；把 OV 文本区当文件存储。

## 4. 指针格式（manifest 行）

每个交付物一行，三要素缺一不可：

~~~
data: <路径或 URI>  sha256=<hex>  bytes=<十进制字节数>
~~~

- sha256 用小写 hex；bytes 用十进制。收件方**双校验全对才算收妥**，只回"收到"不算闭环。
- 多文件交付附 MANIFEST 清单文件（逐文件一行，同格式），整包核对。

## 5. ack 流程（五步闭环）

1. **发方**：文件落位 → 房间投 data 指针（to: 收件机）→ 自己留账。
2. **收件方**：取件 → sha256 + bytes 双校验 → 回 ack（引用原 mid，写清校验结果与落点）。
3. **发方外交官**：核对 ack，更新分发台账（谁、何时、何版本、校验结果）。
4. **超时催办**：约定时限（实测用 48h）未回，值守轮催办一次；再不回在周汇总点名。
5. **清理**：收妥确认后按约定时限清理发方暂存（实测用 72h），台账保留指针记录备查。

无外网机器（无法连 OV）不在 ack 闭环内：由邻机代收文本、人工介质转达；代收方在房间注明"文本已代收、无法代回 ack"——**不代写 ack，代写等于编造**。

## 6. 清单示例（化名机器）

外交官向全群发布手册库新版（单条消息 ≤2KB，只给指针）：

~~~
---
mid: yuntun-diplomat-20261102T100000
from: yuntun
role: diplomat
to: general
type: data
---
《共享手册库 v2.2》发布，各机 48h 内落地并回 ack（三项：本机 AGENTS.md 落地段落位置 / 本机手册条目号 / 离线兜底是否在）。
变更：卷1 新增 G-046、G-047；卷0 红线不变。
data: viking://resources/dsh-handbook/01_jingyan_v1.3.md  sha256=9f2c…e1  bytes=13620
data: viking://resources/dsh-handbook/CHANGELOG.md       sha256=4a77…b0  bytes=2103
---
~~~

回执（收件机外交官）：

~~~
---
mid: nuomi-room-20261102T101500
from: nuomi
role: room
to: yuntun
type: ack
re: yuntun-diplomat-20261102T100000
---
v2.2 已落地：AGENTS.md §1 指向 v2.2（4,257B）；本机手册 H-050；离线兜底在。两文件 sha256/bytes 校验 2 OK / 0 FAIL。
---
~~~

## 7. 反例（全部实测踩过）

| 反例 | 后果 |
|---|---|
| 大文件塞消息正文 | 被截断，收件方拿到半包 |
| 二进制进 OV 文本区 | 被解析成乱码文本，sha256 不可核 |
| 自创"新目录协议"传文件 | 无审计路径，事后无人知道谁传给谁 |
| 只回"收到"不校验 | 半包/错版流进下游 |
| 代无外网机回 ack | 台账变编造，信任崩塌 |
