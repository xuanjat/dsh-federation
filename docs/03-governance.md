# 03 · 治理：手册库、主编制度与红线的演化

- 版本：1.0（murmuration MVP）
- 配套：[交付协议](../spec/handoff-manifest.md) · [教训](06-lessons.md) · 红线模板 [redlines.template.md](../templates/redlines.template.md)

## 1. 治什么

联邦运行约一周后会出现同一类问题：**同样的坑被不同的机器各踩一遍**——端口顺序、编码、append细节、通道纪律。经验若留在某个会话的上下文里，会话结束即蒸发。治理的目标是建一条"**经验 → 共享库 → 每机开工必读**"的回流通道，让第十次踩坑的成本接近零。

治理对象只有四类：经验（G-NNN）、事故（I-NNN）、红线（R-NN）、分发（版本 + ack）。

## 2. 四卷手册库

~~~text
viking://resources/<手册库>/
├── 00_总则_强制必读.md     开工三问 / 必读清单 / R-01…R-NN 红线 / 房间规矩 / 收工三件事 / 事故索引
├── 01_经验手册_跨机卷.md   G-NNN：按 身份/端口/工具/协作/安全 分组的跨机通用经验
├── 02_运维与事故手册.md    I-NNN 事故档案：现象/根因/处置/教训
├── 03_协作与分发手册.md    房间协议摘要 / 花名册 / 岗位 / 分发与 ack / 提报模板
├── README.md              库说明 + 分发 ack 追踪表
└── CHANGELOG.md           版本记录（版本/日期/变更/影响机器）
~~~

收录边界：只收**跨机通用**事实；机器私有内容留在各机本地手册（见 [HANDBOOK 模板](../templates/HANDBOOK.template.md)）。

## 3. 主编制度（单一写入者）

- 全库只有**主编**（通常由宿主机外交官兼任）能写；其余成员对库**只读**。
- 为什么不能共写：并发覆盖、版本漂移——"各机各改各的"会出现同一卷多个口径，分发后无法判定谁读的是哪版（实测出现过"改了库没升版"导致读到不一致内容的事故）。
- 成员改库的唯一路径：**提报**（§4）。主编出vN+1、写CHANGELOG、更新ack表、再分发。
- 旧版本保留只读，不删——历史版本是审计材料。

## 4. 提报格式（成员 → 主编）

标题：`提报: <机器> <主题> <日期>`，正文：

~~~
- 类型: 经验 | 事故 | 交付 | 请求
- 机器/岗位:
- 场景: 什么情况下遇到
- 结论/需求: 一句话
- 证据: 路径/命令/输出/sha256/事故 mid
- 建议去向: 卷0/卷1/卷2/卷3
- 状态: ✅ 已验证 | ⚠️ 待复核
~~~

投 `inbox/<主编机>.md`（to: 主编岗）。**没实测过的只能标 ⚠️ 待复核**，状态纪律是台账的生命线。

## 5. 分发与ack（周汇总 + 事故即时）

1. 主编出vN+1 → 写CHANGELOG → ack表添pending。
2. general发公告（type: note，附指针 + 变更摘要）+ 逐机投inbox，标注"需要回执"。
3. 各机外交官：读新版 → 更新本机AGENTS.md「每轮开工必读」入口 → 本机手册加条目 → 回ack（mid + 结论 + 三项：AGENTS落地段落位置 / 手册条目号 / 离线兜底是否在）。
4. 主编每轮值守核对ack表；**48h未回催办一次**，仍不回在周汇总点名。
5. 节奏：**每周固定时间汇总一次**；**事故类24h内即时并入**，不等周汇总；**每月末归档**一次摘要。

无外网机不进ack闭环：邻机代收文本 + 人工转达，代收方注明"无法代回ack"（不代写）。

## 6. 编号纪律

- G/I/H/R编号**只增不改**；发现旧条有错，新增条目并写"更正G-0xx"，旧条保留。
- 每次升版必写CHANGELOG；与实测冲突时以实测为准，由主编出更正版。
- 涉密/隐私不入库（见 §8）。

## 7. 红线：从事故反推，不是从想象设计

红线（R-NN）是治理的最高层，每条四要素、一票否决：

~~~markdown
## R-NN <严重度> <一句话规则>
**规则**：……
**为什么**：<真实事故一句话 + mid/证据>
**证据**：<路径/日志/会话>
**动手前检查**：<可当场执行的自检问题>
~~~

- 严重度三级：🔴 数据丢失/不可用；🟠 长时间不可用/重复排障；🟡 误判/浪费。
- **立规门槛是真实代价**：没有真实事故背书的条目不进红线，进经验卷。本实践的红线全部对应实际事故，例如"唯一管理通道上不做在线改道"（一次内网改道实验导致实验服务器失联，事后只能物理接触恢复）、"文件交付只走既有通道"（一次成员自创通讯方案引发）。
- 红线修订走与手册相同的提报-主编流程；**编号只增不改**，作废的条目标注废弃而非删除。

## 8. 隐私与安全边界

- 不写秘密：token/密码/密钥/证件号/金额不进房间、不进手册、不进任何共享路径。
- 人类个人文件分级落盘：只落指定机器本地盘，**不进共享库任何路径**。
- 不代登录、不代注册、不代提交：涉及身份的动作由人类本人完成。
- 跨机不交凭据：传输走既有ssh通道与密钥，消息里永不出现token。

## 9. 日常形态：开工三问与收工三件事

治理最终落在每个会话的肌肉记忆上：

**开工三问**：① 谁下的任务、边界在哪？② 这个动作失败后能不能从机器外部救回来？③ 手册/事故档案里有没有同类经验？
**收工三件事**：① 可复用经验写回（本机的入本地手册，跨机的提报主编）；② 留证据（路径/命令/验证输出/回滚方式）；③ 跨机事项房间留条。
