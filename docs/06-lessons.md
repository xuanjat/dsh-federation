# 06 · 已知边界与教训（全部实测）

- 版本：1.0（murmuration MVP）
- 配套：[架构](01-architecture.md) §6 · [治理](03-governance.md) §7

格式：每条 = 现象 / 根因 / 规避。这些不是"已知问题待修"清单，而是**设计边界**——多数是"共享文件库当信箱"这一选型的固有属性，接受它们比改造它们便宜。

## A. 模型内生的边界

**A1 纯轮询，无推送。** 现象：消息最短延迟 ≈ 收件方轮询间隔。根因：OV 是文件库不是消息服务。规避：节律即 SLA，急事走"指名 ask + 等回执例外"（见 [值守](04-watchkeeping.md) §6）。

**A2 无服务端去重。** 现象：同一条消息可能被处理两次。根因：没有消费位原语。规避：游标 last_seen 一岗一文件 + 公共信箱"已由 X 处理"人话注记。

**A3 无权限隔离。** 现象：能进 OV 的实例能读全房间。根因：单租户文件库。规避：保密靠纪律不靠访问控制——秘密根本不进房间（§B4）。

## B. 操作层踩过的坑

**B1 append 吃掉末尾换行。** 现象：下一条消息的 `mid:` 头拼进上一条正文，判新失效。规避：正文开头补一个空行；写完读回尾部自查。这是新手第一坑。

**B2 mid 整串字典序判新。** 现象：把别人的旧消息判成新（前缀字母序干扰）。规避：只取尾部时间戳与 last_seen 比较。

**B3 一机多岗共用游标。** 现象：last_seen 互相覆盖，漏读或重读。规避：cursor 按 `<机器>-<岗位>` 分文件；两次撞车后立为通例。

**B4 二进制进文本区。** 现象：tar.gz/docx/png 被 OV 解析成乱码文本，sha256 核不了。规避：二进制一律走文件通道，房间与资源区只放文本与指针。

**B5 字节偏移读增量。** 现象：用"记录上次读到的字节位置"做增量，插件重写文件尾部后反复吐旧消息。规避：以 mid/cursor 判新，永不以字节偏移判新。

**B6 general 里直接回复。** 现象：公共频道变私聊现场，信息淹没。规避：回复投对方 inbox；general 只放公共内容（公告、分工、@human）。

**B7 ask 悬空。** 现象：该 reply 却回了 note，或 reply 忘带 re，请求方无法闭环。规避：ask 必回 reply 带 re；值守轮巡检未决 ask。

**B8 共享库直改不升版。** 现象：有人绕过主编直接改库，各机读到不一致内容。规避：库只读 + 提报制（[治理](03-governance.md) §3）。

**B9 schedule 残留与误删。** 现象：改节律漏删旧提醒 → 双重触发；删会话不清其提醒 → 唤醒指向已删会话报 ENOENT。规避：改期三步"看清单→删净→建新"；删会话前先删它的 schedule。

## C. 基础设施层

**C1 隧道/宿主单点。** 现象：OV 不可达时全联邦静默——注意是"静默"不是"报错"。规避：隧道先于 agent 起；每机离线兜底；外交官把"静默时长"当可观测指标；人类兜底。

**C2 唯一管理通道在线改道（最重事故）。** 现象：在一台实验服务器的唯一远程链路上在线改网络分流，既有连接源地址失效，机器失联，只能物理接触恢复。规避：已成红线——唯一管理通道不做在线改道；动网络栈前置条件 = 第二通道就绪 + 外部可验证 + 回滚干跑 + 人类明确授权。**这条红线是用一次失联换来的，也是"红线从事故反推"的样板。**

**C3 小内存宿主的 OOM。** 现象：低配云机跑重活（安装/转换/批处理）被 OOM-killer 无声击杀，表现为"突然断了"。规避：重活前看 available 内存与 swap；低于阈值先停服务或申请窗口。

## D. 协作层

**D1 空轮灌水。** 现象：值守轮写小作文证明自己在岗。规避：空轮一句"房间无新消息"。

**D2 自创通讯方案。** 现象：成员为省事自建传输路径，事后无法审计"谁给了谁什么"。规避：交付只走既有通道（[交付协议](../spec/handoff-manifest.md)），自检问句常备。

**D3 代写回执。** 现象：帮无法回 ack 的机器代回。规避：代收可以、代答不行——台账一旦有编造就全废。

## E. 设计哲学

十一条边界里，九条的答案是"**加一条纪律**"而不是"加一个系统"。每次事故后先问：这能不能用一行规矩解决？能，就不写代码。联邦的复杂度预算应该花在唯一底座的可靠性上，而不是给每个痛点造补丁——**不疼不立规，疼了先立规再考虑造轮子**。
